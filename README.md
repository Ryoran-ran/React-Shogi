# 将棋からはじめるボードゲームメーカー

同じ端末で2人が交互に指すほか、簡易AIとの対局やAI同士の動作確認ができる将棋です。盤面の大きさ・初期配置・駒の種類ごとの動きとデザインを編集し、新しい駒も追加できます。

## 起動

Bun が必要です。初回は `bun install` で開発用の型定義を含む依存パッケージをインストールしてください。

```powershell
npm run dev
```

ブラウザで **http://localhost:5173** を開いてください。以前のサーバーが動いている場合は `Ctrl+C` で止めてから起動し直します。編集後はブラウザを再読み込みしてください。

## タイトルから遊び方を選ぶ

起動時はタイトル画面から始まります。

- **普通の将棋**：9×9の平手・パスなしで新しい対局を始めます。2人対局とAI対局を選べます。
- **エディットで遊ぶ**：「新規」「編集」「遊ぶ」のメニューを開きます。「新規」は空の盤面から作成、「編集」は保存した配置を修正、「遊ぶ」は完成済みの配置を選んで直接対局します。配置ファイルから編集・対局することもできます。

保存した配置はプレビュー付きで表示します。作成途中の配置は編集でき、王・玉などの配置を整えると対局できるようになります。

メニューの「コピーして作成」では、元の配置を残して新しい配置を編集できます。名前は「元の名前のコピー」のように重複しない候補を付けます。コピーを開いただけでは保存せず、保存操作を行うと新しい配置として追加します。不要な配置はメニューの「削除」から、確認して削除できます。

前回の対局がある場合は「対局の続きから」で再開できます。終局済みの場合は「前回の対局を見る」で結果や棋譜を確認できます。対局画面や結果画面の「タイトルへ」で戻れます。タイトルやエディットのメニューではAIは進行せず、対局画面へ戻るとモードに応じて再開します。

## 指し方

1. 先手の駒をクリックします。移動できるマスに印が付きます。
2. 移動先をクリックすると、後手の手番になります。
3. 成れる場合は「成る」「成らない」を選びます。行き所がなくなる場合は自動で成ります。
4. 持ち駒をクリックし、印が付いたマスを選ぶと打てます。

選んだ駒をもう一度クリックするか、Esc キーで選択を解除できます。「一手戻す」「盤面を反転」「投了する」「新しく始める」も使えます。

決着すると、勝者・決着理由・手数を結果画面で表示します。AI対局では自分の勝ち負けに合わせて演出が変わります。「終局した盤面を見る」または Esc キーで閉じ、棋譜や盤面を確認できます。「結果を見る」で再表示でき、結果画面から棋譜の保存や次の対局にも進めます。

対局と盤面の向きは、このブラウザに自動保存します。「棋譜を保存」で独自の JSON 形式に書き出し、「棋譜を開く」で続きを再開できます。KIF・CSA 形式には対応していません。以前のメーカーの保存内容は別のキーで残っています。

## 盤面と駒の配置を編集する

タイトルの「エディットで遊ぶ」から「新規」または「編集」でエディット画面を開きます。エディット対局中は画面上部の「配置を編集」からも開けます。編集中はAIを停止し、元の対局を保持します。「編集をやめる」または Esc で、開く前のメニュー・対局へ戻れます。

1. 「横のマス数」「縦のマス数」をそれぞれ3〜15で設定します。長方形にも対応しています。
2. 先手・後手と駒の種類を選び、盤面をクリックして配置・上書きします。「成った駒を置く」で成駒も配置できます。
3. 「消しゴム」で駒を取り除けます。同じ側の王・玉を置き直すと移動します。
4. 「駒の設定画面を開く」から専用画面へ進みます。左の駒一覧で編集する種類を選び、「通常」「成り後」を切り替えて設定できます。移動と駒取りは初期状態では共通で、方向・間隔・回数の変更を両方に反映します。同じ種類の駒すべてに、先手・後手共通で適用します。
5. 最初の手番を選び、「この配置で対局」で新しい対局を始めます。王・玉は各側1枚必要です。手番ではない側が王手を受けている配置や、開始時点で詰んでいる配置は修正してください。

専用画面の「デザイン」では、先手・後手それぞれの表示文字（最大6文字）、駒の色、文字の色、形（将棋型・丸・四角）を設定できます。「通常」「成り後」の見た目も別々に設定でき、プレビューで確認できます。一方のデザインをもう一方へコピーする操作と、片側だけ標準へ戻す操作も利用できます。盤面・配置パレット・持ち駒・保存済み配置のプレビューに反映します。

駒一覧の「＋ 駒を追加」で新しい駒を作成し、「選択中の駒をコピー」で動きとデザインを引き継いだ別の駒を作成できます。追加駒は最大32種類で、名前（最大20文字）と成りの有無を設定できます。新規の駒は動きが空の状態から設定し、成りを有効にしたときは通常時の動きを成り後へコピーします。設定を反映して盤面編集へ戻ると、配置パレットから追加した駒を選べます。追加駒も取ると成り前の持ち駒になり、取った側のデザインで盤面へ打てます。標準の将棋やコピー元の駒は変更しません。

専用画面は「駒一覧」「動きの図」「詳細設定」に分かれています。駒の動きは図の移動先を押して追加・解除します。表示範囲の初期値は5×5で、「−」「＋」により3×3〜29×29を2マス刻みで変更できます。駒は常に図の中央に置きます。「自動調整」では選択中の駒・状態・動作の設定がすべて図に収まる範囲にします。縮小して図の外になった設定は削除せず、「範囲外に○件」と表示します。大きい図はマスの大きさを保って上下左右にスクロールでき、表示範囲を変えると中央の駒に戻ります。表示範囲の変更は駒の動きや取り消し履歴に影響せず、配置データにも含めません。

図は先手の向きで、後手は前後が反転します。各方向の回数は1〜14回または「盤端まで」に設定できます。離れたマスを指定すると、その間を飛び越える動きになります。図の外の移動先は「横」「縦」でそれぞれ最大14マスまで指定して追加できます。空にする操作と、通常／成り後の各状態を標準に戻す操作も利用できます。

「移動と駒取りを別々に設定する」を有効にすると、「移動」「駒取り」を切り替えて個別に設定・コピーできます。この選択は駒の種類・通常／成り後ごとに保存します。共通設定に戻すと「移動」の設定を駒取りにも適用し、「一つ戻す」で元の個別設定に戻せます。以前の保存データで移動と駒取りが異なる駒は、個別設定として開きます。

この画面の変更は下書きとして保持します。「設定を反映して戻る」または Esc で盤面編集へまとめて反映し、「変更せず戻る」では破棄して戻ります。途中の盤面や配置名、保存先などの設定は保持します。駒の選択と「一つ戻す」の履歴はこの画面で独立しており、盤面の配置操作を戻すことはありません。配置のブラウザ保存・ファイル出力は盤面編集で行います。

「移動」は空きマスへ進む動き、「駒取り」は相手の駒があるマスへ進む動きです。王手や王の移動先の安全性、AIの合法手と利きの判定にも編集した設定を使います。盤面編集の「編集を一つ戻す」では、専用画面でまとめて反映した変更を一度に戻せます。「盤面を空にする」とサイズ変更では動きを保持し、「平手に戻す（9×9）」では駒の動きも標準に戻します。編集した駒も、成れる範囲・強制成り・駒打ちなどの将棋ルールは引き継ぎます。

盤面を縮小すると盤外の駒は取り除かれます。「編集を一つ戻す」でサイズや配置を戻せます。「盤面を空にする」「平手に戻す（9×9）」「現在の対局の盤面を使う」も利用できます。現在の盤面を使う場合は持ち駒も引き継ぎます。

編集した盤面でも駒取り・駒打ち・王手・成り・パス・AI対局を使えます。成れる範囲は相手側の端から、縦幅の3分の1（切り捨て、最大3段）です。「新しく始める」「もう一局」では編集した初期配置へ戻ります。通常の9×9へ戻す場合はエディターの「平手に戻す」を使って適用してください。

棋譜には盤面サイズと初期配置も保存します（version 3）。駒の動きだけを編集した対局はversion 4、追加駒やデザインを含む対局はversion 5、盤面のコードだけを含む対局はversion 6、駒のコードを含む対局はversion 7で保存します。「新しく始める」「もう一局」や再読み込みでも設定を引き継ぎます。以前のversion 1・2も、9×9の平手として引き続き読み込めます。

### 配置だけを保存・読み込みする

エディターの「配置の保存と読み込み」では、対局を始めずに編集中の配置を保存できます。王・玉をまだ置いていない作成途中の配置も保存できます。

- **ブラウザに保存**：配置名を付けてローカルストレージに保存します。メニューの「編集」から保存した配置を開けます。複数の配置を最大100件保存できます。
- **上書き保存**：読み込み・保存済みの配置を更新します。元の配置を残したい場合は「別名で保存」を使ってください。
- **別名で保存**：新しい配置名を入力し、ブラウザ保存かファイル出力を選べます。新規作成中でも利用できます。ブラウザ保存では同じ名前の配置への上書きは行わず、新しい配置として追加します。ファイル出力を選んだ場合も、読み込み元のブラウザ保存は変更しません。
- **ファイルに出力**：配置を専用のJSONファイルに書き出します。別のブラウザや端末へ移す場合にも使えます。
- **ファイルを開く**：出力した配置ファイルをエディターへ読み込みます。現在の対局は「この配置で対局」を押すまで保持します。

保存内容は盤面サイズ・駒の配置と成り・種類ごとの移動／駒取り・追加駒の定義・先手／後手のデザイン・ルールコード・持ち駒・最初の手番・パス上限です。動きだけを編集した配置はversion 2、追加駒やデザインを含む配置はversion 3、盤面のコードだけを含む配置はversion 4、駒のコードを含む配置はversion 5、標準の配置は以前と同じversion 1で保存します。以前の配置も引き続き読み込めます。パス上限はエディターでも設定でき、空欄は無制限、0はパスを使用しない設定です。配置名が空欄の場合は「5×7の配置」のように名前を付けます。

「別名で保存」の名前欄では Enter でブラウザに保存できます。キャンセルまたは Esc で名前入力だけを閉じ、編集を続けられます。

配置ファイルには棋譜を含めません。対局の続きを保存する場合は、対局画面の「棋譜を保存」を使ってください。ブラウザ内の配置保存はそのブラウザに保存され、自動同期は行いません。ブラウザのサイトデータを削除すると保存済み配置も消えるため、残したい配置はファイルにも出力できます。

## 追加ルール：パス

パスはエディット対局用の追加ルールです。「普通の将棋」ではパスを使用しません。

「パスする」で盤面と持ち駒を変えずに手番を相手に渡せます。王手中はパスできません。パスも1手として数え、棋譜に「▲パス」「△パス」を記録します。

初期値は無制限です。対局開始前に「パス上限（各自）」へ整数を入力すると、先手・後手それぞれの上限を設定できます。空欄は無制限、0はパスを使用しない設定です。残り回数は画面に表示し、「一手戻す」で使用回数も戻ります。「新しく始める」では上限設定を引き継ぎ、使用回数をリセットします。

AIもパスと残り回数を考慮します。連続パスだけで直ちに終局することはありませんが、無制限では同じ局面が4回現れると千日手になります。回数制限がある場合は残り回数も局面の違いとして扱います。

棋譜の保存・読み込みには、パス履歴と上限設定も含めます。以前の保存形式（version 1）の棋譜はパスなしで読み込むので、パスを使う場合は新しい対局の開始前に設定してください。

## AIで対局・動作確認する

画面上部の対局モードで選びます。

- **自分：先手 / AI：後手**：自分が指すと、AI が後手として応手を指します。
- **自分：後手 / AI：先手**：AI が先手から指します。
- **AI同士（動作確認）**：選択後に「自動開始」を押すと、両側をAIが操作します。
- **AIで1手**：現在の手番を1手だけAIに任せます。2人対局モードでも使えます。

人とAIの対戦はモードを選ぶだけで自動応手します。棋譜の読み込みや、編集画面から対局へ戻った場合も、AIの手番ならそのまま指します。再読み込み後はタイトルの「対局の続きから」で対局を開くと自動応手します。自分の手を「AIで1手」に任せた場合も、相手AIは続けて自動応手します。

「停止」を押すと停止を予約し、思考中の1手を指し終えたところで自動進行を止めます。受付後は「停止予約済み」と表示し、次の手には進みません。思考前の待機中ならその場で停止します。明示的に停止した状態は再読み込み後も保ち、「AIを再開」で自動応手へ戻れます。新しい対局や棋譜を開いた場合は、その対局モードに従って開始します。

人対AIの自動応手中は「待った」で直前の自分の手まで戻せます。AIの応手も戻して自分の手番にするため、戻した直後にAIが指し直すことはありません。AIの思考中に戻した場合は、その結果を破棄します。停止中や2人対局では、従来どおり「一手戻す」で1手だけ戻します。

AI同士は「自動開始」で進め、再読み込み後は停止状態で開きます。途中経過を確認できるよう最大200手ごとに自動停止します。人対AIでは、この200手の自動停止はありません。

「速い」「じっくり」で読む深さと計算量を切り替えられます。AIは駒の価値・利き・成り・王手などを使う簡易探索で、競技用の将棋ソフトほどの強さはありません。ブラウザ内の Worker で動き、APIキーや外部サービスは不要です。

## 対応ルール

- 全8種類の駒と成駒の動き、駒を飛び越えない移動、手番の切り替え。
- 捕獲、成駒を元に戻して持ち駒にする処理、駒打ち、任意・強制の成り。
- 二歩、行き所のない駒打ち、王手放置・自玉を王手にさらす手、打ち歩詰めの禁止。
- 王手表示、詰みの判定、投了、千日手、連続王手の千日手。
- 合意による引き分け。

ルール確認の基準：[日本将棋連盟の対局規則](https://www.shogi.or.jp/match/taikyoku_rules/)。千日手は「指し直し」として対局を終了し、「新しく始める」で再開します。入玉宣言法、持将棋の点数判定、500手による持将棋、持ち時間・秒読み、オンライン対戦は未実装です。

## 開発

```powershell
bun test
bun run typecheck
npm run build
```

`dist/` に静的配信用のファイルを生成します。型検査はアプリとテストを対象とし、Bun用の公式型定義も使います。

- `src/pieces.ts`：既存8種類の駒定義。通常・成り後の動き、表示名、説明、強制成りの段数、AI用の駒の価値。
- `src/pieceeditor.ts`：駒の専用設定画面。独立した下書き・取り消し履歴と、駒一覧・動きの図・詳細設定の表示。
- `src/pieceview.ts`：先手・後手別デザインの盤面・持ち駒・プレビュー用表示。
- `src/movement.ts`：移動・駒取りそれぞれの経路と移動先の判定。
- `src/shogi.ts`：駒定義を使った将棋の状態、合法手、勝敗、棋譜の保存・復元。
- `src/editor.ts`：サイズ変更、駒の配置・消去、編集の取り消し。
- `src/setups.ts`：配置ファイルの検証、名前付き配置のローカルストレージ保存・復元。
- `src/ai.ts`、`src/aiworker.ts`：計算量を制限したAI探索と画面を止めない実行処理。
- `web/app.ts`：盤面、持ち駒、成り選択、棋譜などの操作画面。
- `test/shogi.test.ts`：ルールと保存・復元のテスト。
- `test/pieces.test.ts`：駒定義のコピー、表示名と成り、先後の移動方向、盤面サイズごとの駒打ち制限のテスト。
- `test/piecerules.test.ts`、`test/pieceeditor.test.ts`、`test/piece-editor-ui.test.ts`：駒の動きの検証、専用画面への遷移、下書きの反映・破棄と取り消し、保存・コピー・再開、AI対局、標準将棋の維持のテスト。
- `test/piecelibrary.test.ts`：追加駒・先後別デザイン・成り・捕獲・駒打ち・保存形式と読み込み検証のテスト。
- `test/movement.test.ts`：移動と駒取りの分離、ポーン型の動作、片方だけの動作、経路・距離・跳躍のテスト。
- `test/app.test.ts`：画面の操作ハンドラーを通した対局テスト。
- `test/navigation.test.ts`：タイトルの二分岐、新規・編集・対局、ファイルからの開始、メニュー中のAI停止のテスト。
- `test/human-ai.test.ts`：人対AIの自動応手、再読み込み、停止・再開、待った、200手を超える対局のテスト。
- `test/editor.test.ts`：盤面編集、可変サイズでの対局、初期配置の保存・復元のテスト。
- `test/setups.test.ts`、`test/setup-ui.test.ts`：配置のファイル出力・読み込み、ブラウザ内保存、上書き・複製・削除、保存失敗時のテスト。
- `test/ai.test.ts`：合法手、取り・詰みの選択、AI同士の対局とWorkerのテスト。

将棋の対局ロジックは以前の汎用ルールエンジンから独立しています。現在は盤面サイズ・初期配置・駒の動きとデザインを編集し、新しい種類の駒を追加できます。既存の駒は `src/pieces.ts` の `PIECE_DEFINITIONS` に設定データとしてまとめ、対局処理・画面・AIが参照します。配置ごとの変更は `pieceRules` に保存し、移動／駒取りは `normal`／`promoted`、見た目は `design`、追加駒の定義は `definition` に保持します。標準の定義は変更しません。追加効果と勝利・引き分けの判定は `ruleScript` のJavaScriptコードで拡張できます。

駒の `moves` は空きマスへの移動、`captures` は相手の駒を取る動きを設定する、それぞれ独立した `{ dx, dy, range }` の配列です。共通設定の編集では同じ内容を両方に保存します。個別設定を選んだ状態は `normal`／`promoted` の `separateCapture: true` で保持し、この指定がない旧データでは両配列の動きが異なる場合に個別設定と判定します。既存の将棋の駒には両方に同じ動きを設定しています。どちらかを `[]` にすると、移動だけ・駒取りだけの駒も表せます。王手・王の移動先の安全性・AIの利きの評価には `captures` を使い、空いている攻撃先や味方の駒を守るマスも利きとして扱います。

`dx` は盤面の右方向を正、`dy` は駒の前方を正とし、後手では `dy` の向きを反転します。`range: 1` は指定した移動先へ1回移動し、`range: null` はその方向へ盤端または駒にぶつかるまで繰り返します。正の整数ならその回数まで繰り返します。移動用・駒取り用のどちらの経路も、最初の駒にぶつかると止まります。桂馬は `{ dx: -1, dy: 2, range: 1 }` と `{ dx: 1, dy: 2, range: 1 }` で、途中のマスを調べず移動先を判定します。

例えば、設定データを次のようにすると「前へ1マス進み、斜め前の相手を取る」基本動作を表せます。駒の通常状態と `promotion` の両方に、移動用・駒取り用の配列を設定します。

```ts
moves: [{ dx: 0, dy: 1, range: 1 }],
captures: [
  { dx: -1, dy: 1, range: 1 },
  { dx: 1, dy: 1, range: 1 },
],
```

`promotion` がある駒は成ることができ、成り後の名前・動き・価値を定義します。`promotion.forcedRanks` は、成らずに残れない相手側の端からの段数です（歩・香は1、桂は2、飛・角・銀は0）。この段数は駒打ちの制限にも使います。王手・二歩・打ち歩詰めなどの将棋ルールは対局処理で判定します。保存済みの配置と棋譜は引き続き読み込めます。

## JavaScriptのルールコード

盤面と駒には別々のコードを設定できます。盤面編集の「盤面のルールコードを編集」では、勝利・敗北条件や盤面全体の効果を記述します。「駒の設定画面を開く」→種類を選択→「この駒のルールコード」では、その種類だけの動作を記述します。両方のコードを同じ配置に保存でき、これまでの盤面コードもそのまま利用できます。

駒のコードは同じ種類の先手・後手、通常・成り後で共有します。`ctx.self.side`や`ctx.self.promoted`で条件を付けられます。HPや使用回数などは各駒の`data`に保存し、盤面・全駒で共有する情報には`ctx.state`を使います。

例えば、次のコードを対象の駒へ設定すると、その駒だけが「取られると消滅」します。

```js
export default {
  afterCaptured(ctx) {
    ctx.discardCapture();
  }
};
```

駒のコードのイベントは次の対象に発動します。`ctx.self`はコードを持つ駒の参照用コピーで、`square`・`type`・`side`・`promoted`・`data`・`alive`を参照できます。`ctx.actor`はイベントを起こした駒です。捕獲時には、取る側がactor、取られた側のコードではselfが取られた駒になります。

| イベント | 駒のコードの対象 |
| --- | --- |
| onStart | 開始時に盤面へ配置された各駒 |
| validateMove / beforeMove | これから動かす・打つ駒 |
| beforeCapture / afterCapture | 相手を取る駒 |
| afterCaptured | 相手に取られた駒 |
| afterMove | 動いた・打った駒。自動移動も含む |
| afterDestroy | 破壊された駒 |
| turnStart / turnEnd | その手番の持ち主の駒それぞれ |

各イベントでは盤面のコード、対象となる駒のコードの順に実行します。手番イベントでは盤面のマス番号順に対象を決め、途中で除去・別の種類へ変更された駒を再度動かしません。同じ場所へ新しく生成した駒も、元の駒のイベントを引き継ぎません。取られた・破壊された駒は`ctx.self.alive === false`となり、除去前の情報を参照できます。消えた駒には、その後のafterMoveを発動しません。afterCapturedのself.squareには捕獲先のマスが入るため、そのマスをdestroyすると現在そこにいる捕獲側の駒を破壊できます。

駒の効果と追加イベントをすべて解決した後に、盤面の`checkResult`を実行します。勝利・敗北条件は引き続きここで設定できます。checkResultは盤面専用のイベントです。駒のコードからも`ctx.win`・`ctx.draw`を使えますが、盤面のcheckResultで設定した結果を最終的に使います。捕獲側・捕獲された側・盤面でdiscardCaptureを重ねて呼んでも、捕獲した持ち駒を除外するのは1回です。

駒のコード編集も独立した下書きです。「設定を反映して戻る」で駒設定の下書きへ反映し、さらに駒設定から盤面編集へ反映します。駒設定の「変更せず戻る」では、その中で編集したコードも破棄できます。各段階の取り消し、駒のコピー、新しい種類の駒へのコピー、配置のコピー・別名保存・ファイル出力、待った・保存・再開・AIにも両方のコードを含めます。駒のコードを含む配置はversion 5、棋譜はversion 7で保存し、盤面だけのコードのversion 4／6も引き続き読み込めます。

盤面編集の「盤面のルールコードを編集」から、この配置全体に適用するJavaScriptを記述できます。`if`・ループ・関数・計算・配列・オブジェクトなどを利用できます。「サンプルを読み込む」には、周囲破壊、捕獲された歩の消滅、手番開始時の歩の自動前進、最終段での選択式変身を用意しています。通常の駒の移動先は従来の駒設定で決め、コードから追加効果や指し手の禁止、勝敗判定を設定します。

```js
export default {
  afterCapture(ctx) {
    for (const target of ctx.board.neighbors(ctx.event.to)) {
      if (target.piece && target.piece.side !== ctx.actor.side) {
        ctx.destroy(target.square);
      }
    }
    ctx.state.explosions = (ctx.state.explosions ?? 0) + 1;
  }
};
```

コードは下書きとして編集し、「実行確認」で構文、現在の配置の開始処理、先頭64件までの合法な行動とパスを検証します。確認は盤面を変更しません。「設定を反映して戻る」で盤面編集の履歴へ反映し、「変更せず戻る」または Esc で破棄します。Ctrl+Enter（MacではCommand+Enter）でも実行確認でき、Tabはコード欄へ空白2文字を挿入します。盤面編集での取り消し、配置のコピー、別名保存、ブラウザ保存、ファイル出力、棋譜保存にもコードを含めます。盤面のコードだけを含む配置はversion 4、棋譜はversion 6です。駒のコードを含む場合は配置version 5、棋譜version 7です。従来の保存形式も読み込めます。

### イベント

`export default` に次の名前の同期関数を定義します。必要なイベントだけを記述します。

| 名前 | 実行時点 |
| --- | --- |
| `onStart` | 初期配置から対局を開始するとき |
| `validateMove` | 指し手を適用する前。`false`で禁止 |
| `beforeMove` | 通常の指し手を適用する前。駒打ち・パスも対象 |
| `beforeCapture` | 通常・自動移動で相手を捕獲する直前 |
| `afterCapture` | 相手を捕獲して、持ち駒に加えた後 |
| `afterCaptured` | 取られた駒への通知。盤面でも捕獲情報を参照可能 |
| `afterMove` | 通常・自動移動・駒打ちの後。パスでは発生しない |
| `afterDestroy` | 破壊で盤面から除去された後 |
| `turnEnd` | 指した側の手番終了時 |
| `turnStart` | 次の側の手番開始時。初期配置でも1回発生 |
| `checkResult` | 一連の効果が終わり、通常の王手・勝敗を判定する前 |

基本の順序は、validateMove → beforeMove → 捕獲・移動 → afterCapture → afterCaptured → afterMove → turnEnd → 手番交代 → turnStart → checkResultです。効果による変更は即座に盤面へ適用し、追加のafterMove・afterCapture・afterCaptured・afterDestroyは発生順のキューで処理します。beforeCaptureは捕獲処理の中で同期的に呼びます。このイベントで元や先の駒を除去・交換すると、その手はエラーになります。捕獲後の消滅にはafterCapture／afterCapturedの`discardCapture()`を使ってください。

### スクリプトAPI

マス番号は左上の0から横方向に並びます。先後のIDは`"sente"`／`"gote"`、駒のIDは`"P"`、`"R"`、`"custom_1"`などです。`ctx.event`には`from`・`to`・`piece`・`captured`・`side`・`automatic`・`pass`がイベントに応じて入ります。`ctx.actor`は対象の駒の参照用コピー、`ctx.side`は盤面コードではイベントの側、駒コードではその駒の持ち主、`ctx.turn`は手番、`ctx.ply`は完了した手数です。

| API | 動作 |
| --- | --- |
| `ctx.board.at(マス)` | 駒またはnullのコピー |
| `ctx.board.pieces(先後?)` | `{square, piece}`の配列 |
| `ctx.board.neighbors(マス, 範囲=1)` | 周囲の`{square, piece}`の配列。中心を除外 |
| `ctx.board.forward(マス, 先後, 歩数=1)` | 前方のマス番号。場外ならnull |
| `ctx.hands`／`ctx.pieceTypes` | 持ち駒の参照用コピー／使用可能な駒のID配列 |
| `ctx.move(元, 先)` | 空きマスへ自動移動 |
| `ctx.capture(元, 先)` | 指定先へ自動移動し、相手がいれば捕獲 |
| `ctx.destroy(マス)` | 持ち駒にせず除去 |
| `ctx.discardCapture()` | afterCapture／afterCaptured内で、捕獲した駒を持ち駒から除外 |
| `ctx.spawn(マス, 種類, 先後, 成り=false)` | 空きマスに駒を生成 |
| `ctx.transform(マス, 種類, 成り=false)` | 種類を変更し、先後と独自データを維持 |
| `ctx.choose(見出し, 候補配列)` | 選択された文字列。候補は文字列または`{value,label}` |
| `ctx.choosePiece(マス, 種類配列, 見出し?)` | 選択した駒へ変身 |
| `ctx.state` | 対局全体の独自データ。フィールドを変更して保存 |
| `ctx.setPieceData(マス, オブジェクト)` | 駒ごとの独自データを設定。参照は駒の`data` |
| `ctx.random()` | 再現可能な0以上1未満の乱数 |
| `ctx.reject(理由?)` | この指し手を禁止 |
| `ctx.win(先後)`／`ctx.draw()` | 勝利・引き分けを確定 |
| `ctx.log(文字列)` | 棋譜の効果履歴へ記録 |

自動移動は駒の通常の移動設定を経由せず、指定したマスへ動かします。イベントの`automatic`で通常の操作と区別でき、無条件に自動移動を繰り返す連鎖を避ける条件も書けます。王が破壊・変身などで消えると、残った側が勝ち、両方が消えると引き分けになります。`win`・`draw`で明示した結果を優先し、それ以外は効果が完了した盤面で王の安全性と将棋の勝敗を判定します。

選択は指し手を行う側が行い、成りの選択と併用できます。選択の結果を指し手に記録し、AIでは各選択肢を別の手として探索します。開始時のonStart・turnStartでは選択を要求できません。コードは合法手の判定やAIの探索でも繰り返し実行するため、モジュール内の変数は手ごとに初期化します。継続する情報は`ctx.state`か駒の`data`に置いてください。独自データ・乱数・自動効果も待ったと保存・復元の対象です。コードから手数を参照できるため、手数や独自データの異なる局面は別の局面として扱います。

JavaScriptの実行には[QuickJS](https://github.com/justjake/quickjs-emscripten)を使用し、ブラウザ・通信・ファイル・外部importから独立させています。同期実行のみ対応し、Dateは使わず、乱数はctx.random()を使います。コード上限30,000文字、各実行のメモリ16MiB、スタック512KiB、割り込み回数256回または150ms、1手256操作・128イベント・4回の選択（各32候補）、選択分岐の探索128回までです。エラー・過剰な処理・保存できない独自データはその手全体を取り消します。

実装は`src/rulescript.ts`（API・イベント・サンプル）、`src/scriptvm.ts`（独立実行環境）、`src/scripteditor.ts`（編集画面）、`test/rulescript.test.ts`／`test/piecescript.test.ts`／`test/script-ui.test.ts`（盤面・駒のルールと画面の検証）です。配信用の実行エンジンはBunで単一ファイルにまとめ、開発サーバーと静的配信の両方で利用します。

`bun run dev`／`npm run dev`はwatchモードで起動し、サーバーの変更時に再起動します。既に古いコマンドで起動していたサーバーは、一度停止して起動し直してください。起動時の読み込みに失敗した場合は、エラーの詳細と再読み込みボタンを表示します。`test/startup.test.ts`は実際のHTTP配信からモジュールを取得し、ブラウザーで解決できるimportであること、Nodeのprocessを使わずタイトル画面・スクリプトを実行できること、読み込み失敗時の表示を検証します。
