# 将棋からはじめるボードゲームメーカー

同じ端末で2人が交互に指すほか、簡易AIとの対局やAI同士の動作確認ができる将棋です。盤面の大きさ・初期配置・駒の種類ごとの動きとデザインを編集し、新しい駒も追加できます。

## 起動

Bun が必要です。初回は `bun install` で開発用の型定義を含む依存パッケージをインストールしてください。

```powershell
npm run dev
```

ブラウザで **http://localhost:5173** を開いてください。以前のサーバーが動いている場合は `Ctrl+C` で止めてから起動し直します。編集後はブラウザを再読み込みしてください。

## タイトルから遊び方を選ぶ

起動時はタイトル画面から始まります。

- **普通の将棋**：9×9の平手・パスなしで新しい対局を始めます。2人対局とAI対局を選べます。
- **エディットで遊ぶ**：「新規」「編集」「遊ぶ」のメニューを開きます。「新規」は空の盤面から作成、「編集」は保存した配置を修正、「遊ぶ」は完成済みの配置を選んで直接対局します。配置ファイルから編集・対局することもできます。
- **Special**：共通エディターで作ったチェスなどの作例を開きます。駒の追加、動き・デザイン・ルールコードの編集、2人対局・AI対局を利用できます。

保存した配置はプレビュー付きで表示します。作成途中の配置は編集でき、王・玉などの配置を整えると対局できるようになります。

メニューの「コピーして作成」では、元の配置を残して新しい配置を編集できます。名前は「元の名前のコピー」のように重複しない候補を付けます。コピーを開いただけでは保存せず、保存操作を行うと新しい配置として追加します。不要な配置はメニューの「削除」から、確認して削除できます。

前回の対局がある場合は「対局の続きから」で再開できます。終局済みの場合は「前回の対局を見る」で結果や棋譜を確認できます。対局画面や結果画面の「タイトルへ」で戻れます。タイトルやエディットのメニューではAIは進行せず、対局画面へ戻るとモードに応じて再開します。

### Specialと編集ガイドライン

Specialの「チェスで遊ぶ」は、共通の対局画面でチェスの標準配置から始めます。「編集する」は、既存の盤面エディターにチェスの設定データを読み込みます。盤面サイズ・配置・駒の追加・移動／駒取り・先後別デザイン・駒と盤面のコードを編集し、独自のゲームとして保存できます。SpecialのメニューではAIを停止します。

編集可能な範囲は縦・横それぞれ3〜15マス、追加駒32種類、移動先の指定は縦・横それぞれ14マス、各状態・各動作64件、コードは各欄30,000文字までです。

`src/special.ts`でゲームを登録し、編集方針を`guidelines`（範囲内なら編集対象）または`play-only`（対局専用）に分けます。エディターへ渡す前に`assertSpecialEditorAllowed`で方針と実際のデータの上限を確認します。上限を超えるゲームは、将来専用の対局処理を追加する対象です。

### エディターで作ったチェス

`src/presets.ts`の`createChessPreset()`は、通常の配置ファイルと同じ`shogi-setup`を返します。チェスの対局にも将棋と同じ`ShogiGame`、駒の設定、コード実行環境、AI Workerを使用します。

- 8×8の盤面、持ち駒なし、成り範囲なし、指し手がなく王手でもない場合は引き分け、という基本設定です。クリーム色と緑の市松模様に白黒の駒を置き、白・黒の手番、a〜h／1〜8の座標、「e2 → e4」の棋譜を表示します。盤面を反転すると座標も反転します。内部では白が先手、黒が後手に対応します。
- キング・クイーン・ルーク・ビショップ・ナイト・ポーンは6種類の追加駒です。移動と駒取りの方向は通常の設定データで定義します。「デザイン」の「チェス型」で6種類のシルエットを選び、両側の色・輪郭の色・向きの固定も変更できます。描画は外部フォントに依存しないSVGです。
- ポーンの初手2マス・アンパッサン・最終段での昇格はポーンのコード、キャスリングはキングのコード、移動済みの記録は駒の個別データで表します。昇格先は初期データの`promotions`に種類のIDを指定して変更でき、追加した駒も指定できます。キングを2マス動かすとキャスリングします。
- 同一局面の数え方、3回・50手の申請、5回・75手の自動引き分け、一般的な戦力不足による引き分けは盤面のコードです。自動引き分けと同じ手で詰みが成立した場合は詰みを優先します。参考：[FIDE Laws of Chess](https://handbook.fide.com/chapter/E012023)。任意の配置でのデッドポジションの完全判定、持ち時間、タッチムーブ、大会の審判手続きは扱いません。
- AIは共通の簡易探索を使います。チェスの各駒には位置ごとの評価表を設定してあり、駒設定の「AI用の駒の価値」「AIの配置評価」で編集できます。過去の同一局面への往復を減点します。強いチェスエンジンを目的とするものではありません。

共通エディターのUndo／Redo、下書き自動保存・復元、テスト対局、実行ログ、コピー・別名保存、ブラウザ保存、JSON出力を利用できます。保存したチェスの作例は「エディットで遊ぶ」の一覧にも表示されます。盤面や駒の動きを変更した場合は、必要に応じて特殊動作のコードも編集してください。

以前に保存したチェスは、その見た目を維持します。配置編集の「盤面の見た目」→「チェスの見た目を適用」で、新しい盤面・駒・座標の表示に変更できます。配置、編集した動き・駒の個別データ・コードは維持し、Undoで戻せます。「表示スタイル」では将棋風／チェス風の座標と先後の呼び名を切り替え、各マスの色は個別に編集できます。この表示設定またはチェス型の駒を含む配置はversion 9、棋譜はversion 11で保存します。以前の配置・棋譜も引き続き読み込めます。

対局は共通の`shogi-game.v1`へ自動保存します。別の対局を始めると、将棋・チェスとも同じ対局枠を置き換えます。棋譜と配置のJSONには編集した設定・コードも含みます。以前の専用形式のチェスJSON、PGN、FENは「棋譜を開く」から共通形式へ変換して読み込めます。以前の`special-chess.v1`が残っている場合は、Specialに「以前のチェスを読み込む」が表示されます。元の保存は削除しません。旧配置JSONは棋譜として読み込んでから「配置を編集」で開けます。現在の編集内容の書き出しは共通のJSON形式です。

### はさみ将棋

Specialの「はさみ将棋で遊ぶ」で、9×9盤・双方9枚の対局を始められます。先手は「歩」、後手は「と」のデザインです。すべての駒が縦横の空きマスへ好きな距離を移動し、駒を飛び越えたり、相手の駒の上へ直接移動したりすることはできません。移動した駒から見て縦横に連続する相手の駒を、自分の駒で挟むとまとめて取れます。斜めには取りません。自分から挟まれる場所へ移動しても、その駒は自動では取られません。

端・角の包囲取りも有効です。移動した駒に隣接する相手の一団が盤端に接し、その一団の周囲に空きマスがなければ取れます。角のマスを含む一団は「角」、それ以外の盤端の一団は「端」の設定で判定します。すべての取りを除去前の盤面から同時に決め、取った駒は再使用しません。この作例は先に5枚取ると勝ち、相手の駒がなくなった場合も勝ちです。同一局面4回は引き分けです。

動きとデザインは追加駒1種類の設定、挟み取りと勝敗は`src/hasamipreset.ts`の編集可能な盤面コードで構成しています。専用の対局エンジンは使いません。Specialの「編集する」から、盤面・配置・駒・コードを変更でき、盤面コード先頭の`WIN_CAPTURE_COUNT`、`CAPTURE_EDGE`、`CAPTURE_CORNER`で勝利枚数と端・角の包囲取りを変更できます。人同士・AI対戦、Undo、テスト対局、下書き復元、コピー・別名保存、ブラウザ保存・JSON出力、棋譜の再開も共通の機能です。作例データは選択時だけ読み込みます。

移動・挟み取り・端の包囲取りは[日本将棋連盟の説明](https://www.shogi.or.jp/knowledge/hasami_shogi/)を参考にしています。同ページの「3枚差で相手に取り返す機会を与える」勝利条件は、この作例の初期ルールには含めず、5枚先取にしています。

### オセロ

Specialの「オセロで遊ぶ」で、黒から交互に8×8盤へ石を置きます。印のある空きマスを押すと配置でき、縦・横・斜めにはさんだ相手の石がすべて反転します。置ける場所がない側だけ「パスする」を使えます。両側とも置けなくなると、空きマスがあっても終局し、石の多い側が勝ち、同数なら引き分けです。盤上の黒・白の枚数を表示します。人同士、人対AI、AI同士、Undo、棋譜保存・再開を共通の対局画面で利用できます。

専用のオセロエンジンは使わず、`src/othellopreset.ts`で共通の`shogi-setup`を作っています。追加駒1種類の丸形デザイン、移動なし、持ち駒なし、王なしの設定を使い、配置できる条件・反転・パス・枚数による勝敗は編集可能な盤面コードです。AIも共通の簡易探索で、石の配置評価表を利用します。

Specialの「編集する」から盤面、初期配置、石のデザイン、評価表、ルールコードを編集できます。コピー・別名保存・下書き復元・テスト対局・ブラウザ保存・JSON出力も同じエディターを使います。オセロの作例データは選択時に読み込み、タイトルや通常の将棋では読み込みません。

共通エディターには「盤外からの配置」を追加しました。指定した種類の駒を、持ち駒を消費せず空きマスに配置できます。1種類なら配置先を直接クリックし、複数種類なら盤面下の「配置」で選びます。配置制限や効果は通常の`validateMove`／`afterMove`で編集でき、`ctx.event.drop`で種類を参照できます。「盤上の駒数を表示」と先後別の「表示記号」も変更できます。これらの新しい設定を含む配置はversion 11、棋譜はversion 13で保存します。既存の将棋・チェスの保存形式は維持します。

### 将棋VSチェス

Specialの「将棋VSチェス」で、共通の9×9盤を使った対戦を始められます。先手は通常の将棋20枚、後手はチェス16枚です。チェスの初期配置は左から8列で、右端1列は空きにし、対局中は両側とも9列すべてを使えます。

- 将棋側は通常の移動・成り・二歩・打ち歩詰めの禁止を使い、取ったチェス駒も持ち駒として打てます。チェス駒は打った後も元の種類の動きを使います。取ったポーンは最終段以外へ打てますが、打った後の初手2マス移動はできません。
- チェス側は取った駒を持ち駒にせず除去します。ポーンの初手2マス、アンパッサン、9段目での選択式昇格、元のルークとのキャスリングを使います。キャスリング中の通過マスには、将棋駒の利きも判定します。
- 両側とも王手放置はできず、王・キングを詰ませると勝ちです。王手でないのに指せる手がない場合は、将棋側は負け、チェス側は引き分けです。
- 共通の反復条件は同一局面4回です。連続王手の反復は将棋側だけ王手側の負けとします。チェス側は同一局面3回・50手の申請を使え、75手は自動引き分けです。駒打ち・捕獲・歩／ポーンの移動で静かな手数をリセットします。持ち駒を含むため通常チェスの戦力不足による自動引き分けは使いません。独自モードの初期方針であり、盤面コードから変更できます。

「編集する」では配置・駒の動き・デザイン・コードに加え、「先後で異なるルール」で表示名、王手、持ち駒、二歩、打ち歩詰め、成り範囲、指し手がない場合の勝敗、連続王手の反復を側ごとに設定できます。「共通設定を使用」で基本ルールへ戻します。Undo／Redo、下書き復元、テスト対局、コピー・別名保存、ブラウザ保存、JSON出力にも対応します。先後を交換すると側ごとの設定も交換します。個々の駒の動作は、交換後の配置に合わせて必要に応じてコード・初期データを調整してください。

先後別設定を含む配置はversion 10、棋譜はversion 12です。ルールコードでは`ctx.settingsFor("sente")`／`ctx.settingsFor("gote")`で各側に適用する設定を参照し、`ctx.event.drop`で駒打ちの種類を参照できます。以前のチェス・将棋の設定や保存形式は維持します。

チェスと将棋VSチェスの反復履歴は、最初の局面と以降の変更部分で保存します。比較時には元の局面を正確に復元し、ハッシュの一致だけで反復と判定することや、古い履歴を切り捨てることはしません。独自データの上限20,000文字を維持したまま、長い対局の容量超過を防ぎます。実装は`src/chessscript.ts`です。

以前の標準ルールコードは、対局・配置・下書きの読み込み時に修正版へ更新します。保存済みの指し手を再現して履歴を作り直すため、途中の対局を続けられます。変更してあるルールコードは自動更新の対象にしません。

## 指し方

1. 先手の駒をクリックします。移動できるマスに印が付きます。
2. 移動先をクリックすると、後手の手番になります。
3. 成れる場合は「成る」「成らない」を選びます。行き所がなくなる場合は自動で成ります。
4. 持ち駒をクリックし、印が付いたマスを選ぶと打てます。

選んだ駒をもう一度クリックするか、Esc キーで選択を解除できます。「一手戻す」「盤面を反転」「投了する」「新しく始める」も使えます。

決着すると、勝者・決着理由・手数を結果画面で表示します。AI対局では自分の勝ち負けに合わせて演出が変わります。「終局した盤面を見る」または Esc キーで閉じ、棋譜や盤面を確認できます。「結果を見る」で再表示でき、結果画面から棋譜の保存や次の対局にも進めます。

対局と盤面の向きは、このブラウザに自動保存します。「棋譜を保存」で独自の JSON 形式に書き出し、「棋譜を開く」で続きを再開できます。KIF・CSA 形式には対応していません。以前のメーカーの保存内容は別のキーで残っています。

## 盤面と駒の配置を編集する

タイトルの「エディットで遊ぶ」から「新規」または「編集」でエディット画面を開きます。エディット対局中は画面上部の「配置を編集」からも開けます。編集中はAIを停止し、元の対局を保持します。「編集をやめる」または Esc で、開く前のメニュー・対局へ戻れます。

1. 「横のマス数」「縦のマス数」をそれぞれ3〜15で設定します。長方形にも対応しています。
2. 先手・後手と駒の種類を選び、盤面をクリックして配置・上書きします。「成った駒を置く」で成駒も配置できます。
3. 「消しゴム」で駒を取り除けます。同じ側の王・玉を置き直すと移動します。
4. 「駒の設定画面を開く」から専用画面へ進みます。左の駒一覧で編集する種類を選び、「通常」「成り後」を切り替えて設定できます。移動と駒取りは初期状態では共通で、方向・間隔・回数の変更を両方に反映します。同じ種類の駒すべてに、先手・後手共通で適用します。
5. 最初の手番を選び、「この配置で対局」で新しい対局を始めます。標準設定では王・玉は各側1枚必要です。王の役割と王手の判定は変更できます。王手を判定する場合は、手番ではない側が王手を受けている配置や、開始時点で詰んでいる配置を修正してください。

専用画面の「デザイン」では、先手・後手それぞれの表示文字（最大6文字）、駒の色、文字の色、形（将棋型・丸・四角・チェス型）を設定できます。チェス型は表示文字に代わり6種類のシルエットを選び、文字の色に代わり輪郭の色を設定します。「通常」「成り後」の見た目も別々に設定でき、プレビューで確認できます。一方のデザインをもう一方へコピーする操作と、片側だけ標準へ戻す操作も利用できます。盤面・配置パレット・持ち駒・保存済み配置のプレビューに反映します。

駒一覧の「＋ 駒を追加」で新しい駒を作成し、「選択中の駒をコピー」で動きとデザインを引き継いだ別の駒を作成できます。追加駒は最大32種類で、名前（最大20文字）と成りの有無を設定できます。新規の駒は動きが空の状態から設定し、成りを有効にしたときは通常時の動きを成り後へコピーします。設定を反映して盤面編集へ戻ると、配置パレットから追加した駒を選べます。追加駒も取ると成り前の持ち駒になり、取った側のデザインで盤面へ打てます。標準の将棋やコピー元の駒は変更しません。

専用画面は「駒一覧」「動きの図」「詳細設定」に分かれています。駒の動きは図の移動先を押して追加・解除します。表示範囲の初期値は5×5で、「−」「＋」により3×3〜29×29を2マス刻みで変更できます。駒は常に図の中央に置きます。「自動調整」では選択中の駒・状態・動作の設定がすべて図に収まる範囲にします。縮小して図の外になった設定は削除せず、「範囲外に○件」と表示します。大きい図はマスの大きさを保って上下左右にスクロールでき、表示範囲を変えると中央の駒に戻ります。表示範囲の変更は駒の動きや取り消し履歴に影響せず、配置データにも含めません。

図は先手の向きで、後手は前後が反転します。各方向の回数は1〜14回または「盤端まで」に設定できます。離れたマスを指定すると、その間を飛び越える動きになります。図の外の移動先は「横」「縦」でそれぞれ最大14マスまで指定して追加できます。空にする操作と、通常／成り後の各状態を標準に戻す操作も利用できます。

「移動と駒取りを別々に設定する」を有効にすると、「移動」「駒取り」を切り替えて個別に設定・コピーできます。この選択は駒の種類・通常／成り後ごとに保存します。共通設定に戻すと「移動」の設定を駒取りにも適用し、「一つ戻す」で元の個別設定に戻せます。以前の保存データで移動と駒取りが異なる駒は、個別設定として開きます。

この画面の変更は下書きとして保持します。「設定を反映して戻る」または Esc で盤面編集へまとめて反映し、「変更せず戻る」では破棄して戻ります。途中の盤面や配置名、保存先などの設定は保持します。駒の選択と「一つ戻す」の履歴はこの画面で独立しており、盤面の配置操作を戻すことはありません。配置のブラウザ保存・ファイル出力は盤面編集で行います。

「移動」は空きマスへ進む動き、「駒取り」は相手の駒があるマスへ進む動きです。王手や王の移動先の安全性、AIの合法手と利きの判定にも編集した設定を使います。盤面編集の「編集を一つ戻す」では、専用画面でまとめて反映した変更を一度に戻せます。「盤面を空にする」とサイズ変更では動きを保持し、「平手に戻す（9×9）」では駒の動きも標準に戻します。編集した駒も、成れる範囲・強制成り・駒打ちなどの将棋ルールは引き継ぎます。

盤面を縮小すると盤外の駒は取り除かれます。「編集を一つ戻す」でサイズや配置を戻せます。「盤面を空にする」「平手に戻す（9×9）」「現在の対局の盤面を使う」も利用できます。現在の盤面を使う場合は持ち駒も引き継ぎます。

編集した盤面でも駒取り・駒打ち・王手・成り・パス・AI対局を使えます。成れる範囲は相手側の端から、縦幅の3分の1（切り捨て、最大3段）です。「新しく始める」「もう一局」では編集した初期配置へ戻ります。通常の9×9へ戻す場合はエディターの「平手に戻す」を使って適用してください。

棋譜には盤面サイズと初期配置も保存します（version 3）。駒の動きだけを編集した対局はversion 4、追加駒やデザインを含む対局はversion 5、盤面のコードだけを含む対局はversion 6、駒のコードを含む対局はversion 7、基本ルールや駒の役割・初期データを含む対局はversion 8、追加の終局設定・向き固定・AI評価表・引き分け申請を含む場合はversion 9で保存します。「新しく始める」「もう一局」や再読み込みでも設定を引き継ぎます。以前のversion 1・2も、9×9の平手として引き続き読み込めます。

### 配置だけを保存・読み込みする

エディターの「配置の保存と読み込み」では、対局を始めずに編集中の配置を保存できます。王・玉をまだ置いていない作成途中の配置も保存できます。

- **ブラウザに保存**：配置名を付けてローカルストレージに保存します。メニューの「編集」から保存した配置を開けます。複数の配置を最大100件保存できます。
- **上書き保存**：読み込み・保存済みの配置を更新します。元の配置を残したい場合は「別名で保存」を使ってください。
- **別名で保存**：新しい配置名を入力し、ブラウザ保存かファイル出力を選べます。新規作成中でも利用できます。ブラウザ保存では同じ名前の配置への上書きは行わず、新しい配置として追加します。ファイル出力を選んだ場合も、読み込み元のブラウザ保存は変更しません。
- **ファイルに出力**：配置を専用のJSONファイルに書き出します。別のブラウザや端末へ移す場合にも使えます。
- **ファイルを開く**：出力した配置ファイルをエディターへ読み込みます。現在の対局は「この配置で対局」を押すまで保持します。

保存内容は盤面サイズ・駒の配置と成り・種類ごとの移動／駒取り・追加駒の定義・先手／後手のデザイン・ルールコード・持ち駒・最初の手番・パス上限・基本ルール・駒の役割と初期データです。動きだけを編集した配置はversion 2、追加駒やデザインを含む配置はversion 3、盤面のコードだけを含む配置はversion 4、駒のコードを含む配置はversion 5、基本ルールや駒の役割・種類の初期データを含む配置はversion 6、追加の終局設定・向き固定・AI評価表を含む配置はversion 7、標準の配置は以前と同じversion 1で保存します。以前の配置も引き続き読み込めます。パス上限はエディターでも設定でき、空欄は無制限、0はパスを使用しない設定です。配置名が空欄の場合は「5×7の配置」のように名前を付けます。

「別名で保存」の名前欄では Enter でブラウザに保存できます。キャンセルまたは Esc で名前入力だけを閉じ、編集を続けられます。

配置ファイルには棋譜を含めません。対局の続きを保存する場合は、対局画面の「棋譜を保存」を使ってください。ブラウザ内の配置保存はそのブラウザに保存され、自動同期は行いません。ブラウザのサイトデータを削除すると保存済み配置も消えるため、残したい配置はファイルにも出力できます。

## 追加ルール：パス

パスはエディット対局用の追加ルールです。「普通の将棋」ではパスを使用しません。

「パスする」で盤面と持ち駒を変えずに手番を相手に渡せます。王手中はパスできません。パスも1手として数え、棋譜に「▲パス」「△パス」を記録します。

初期値は無制限です。対局開始前に「パス上限（各自）」へ整数を入力すると、先手・後手それぞれの上限を設定できます。空欄は無制限、0はパスを使用しない設定です。残り回数は画面に表示し、「一手戻す」で使用回数も戻ります。「新しく始める」では上限設定を引き継ぎ、使用回数をリセットします。

AIもパスと残り回数を考慮します。連続パスだけで直ちに終局することはありませんが、無制限では同じ局面が4回現れると千日手になります。回数制限がある場合は残り回数も局面の違いとして扱います。

棋譜の保存・読み込みには、パス履歴と上限設定も含めます。以前の保存形式（version 1）の棋譜はパスなしで読み込むので、パスを使う場合は新しい対局の開始前に設定してください。

### マスごとの色

盤面エディターの「マスの色」で色を選び、マスをクリックすると背景色を塗れます。駒があるマスも、その配置を保ったまま塗れます。「クリックしたマスを標準色に戻す」で色を消し、「全マスをこの色にする」「すべての色をリセット」で一括変更できます。「市松模様にする」では2色を交互に塗ります。

色の変更もUndo／Redo、下書きの復元、コピー・別名保存、ブラウザ保存、JSON出力の対象です。サイズ変更では座標を維持して拡張・切り詰め、反転・先後交換では駒と一緒に色も移します。範囲コピーは色も含みます。「盤面を空にする」は駒を取り除き、マスの色は保持します。対局画面と保存済み配置のプレビューにも反映し、表示を反転しても同じマスに色が対応します。

色は見た目の設定で、合法手や同一局面の判定には使いません。色を含む配置はversion 8、棋譜はversion 10で保存し、以前の形式の読み込みにも対応します。

## AIで対局・動作確認する

画面上部の対局モードで選びます。

- **自分：先手 / AI：後手**：自分が指すと、AI が後手として応手を指します。
- **自分：後手 / AI：先手**：AI が先手から指します。
- **AI同士（動作確認）**：選択後に「自動開始」を押すと、両側をAIが操作します。
- **AIで1手**：現在の手番を1手だけAIに任せます。2人対局モードでも使えます。

人とAIの対戦はモードを選ぶだけで自動応手します。棋譜の読み込みや、編集画面から対局へ戻った場合も、AIの手番ならそのまま指します。再読み込み後はタイトルの「対局の続きから」で対局を開くと自動応手します。自分の手を「AIで1手」に任せた場合も、相手AIは続けて自動応手します。

「停止」を押すと停止を予約し、思考中の1手を指し終えたところで自動進行を止めます。受付後は「停止予約済み」と表示し、次の手には進みません。思考前の待機中ならその場で停止します。明示的に停止した状態は再読み込み後も保ち、「AIを再開」で自動応手へ戻れます。新しい対局や棋譜を開いた場合は、その対局モードに従って開始します。

AIは、画面側で先に1つの合法手を確認し、Workerでより良い手を探します。「速い」は依頼から約350ms、「じっくり」は約1秒で、その時点の確認済み候補を着手します。Workerが読み込み中・無応答・エラーでも、確認済みの合法手があれば対局を進めます。最初の合法手を確認する処理は約250msを上限とし、個々のコード実行にも既存の上限を適用します。指せる手がない場合やルールコード自体を確認できない場合は、理由を表示して停止します。

将棋・チェスとも、評価が近い上位6候補から、良い評価ほど選ばれやすい抽選を行います。序盤は候補を広くし、16手進むと狭め、60手進んだ場合または王以外が持ち駒を含め6枚以下ならさらに狭めます。許容する評価差は、その配置に存在する王以外の最も価値の低い駒の18%／6%／2%です。探索で分かった詰み・強制敗北は最も良い評価の手を優先し、許容差を超える損をする手や、同じ深さで評価を確定できていない手を抽選に含めません。変化を付ける目的でパスを選ぶこともありません。簡易探索のため、読み切れていない先の詰みや損まで保証するものではありません。

画面からは着手ごとに新しい`randomSeed`、現在の手数`ply`、直近12手の`recentMoves`をAIへ渡します。相手の手で盤面が変わっても、直前の自分の手をすぐ戻すだけの動きは小さく減点します。捕獲・成り・王手からの回避には、この往復の減点を加えません。実際に選んだ手は従来どおり棋譜へ保存するため、再読み込み時に指し手が変わることはありません。`chooseAIMove()`をコードから呼ぶ場合、乱数シードを省略すれば再現用の選び方になり、同じシード・局面・手数・着手履歴と同じ探索結果からは同じ手を選びます。思考時間とノード数の上限は維持します。

独自の配置評価表がない駒は、相手の利きがない空きマスへ動ける範囲も評価します。飛車・角などの通り道を広げる手を評価し、盤面が詰まった時に玉だけが往復し続ける偏りを減らします。駒に明示したAI配置評価表は引き続き利用します。探索の初手候補は浅い評価順に並べ、短い制限時間でも有望な手から読めるようにします。

Workerの受信処理を非同期の初期化より先に登録し、初手の依頼が取りこぼされないようにします。通常はWorkerを使い続け、毎手のルール実行環境の読み込みを省きます。読み込み中の古い依頼や、着手・停止・画面移動後に届いた結果は使いません。探索途中でも確認できた候補を順に送るため、期限までに探索全体が終わる必要はありません。5秒以上応答がないWorkerは交換しますが、交換を待たずに確認済みの手で進めます。時間はブラウザーの処理負荷やルールコードの実行により多少前後します。

人対AIの自動応手中は「待った」で直前の自分の手まで戻せます。AIの応手も戻して自分の手番にするため、戻した直後にAIが指し直すことはありません。AIの思考中に戻した場合は、その結果を破棄します。停止中や2人対局では、従来どおり「一手戻す」で1手だけ戻します。

AI同士は「自動開始」で進め、再読み込み後は停止状態で開きます。途中経過を確認できるよう最大200手ごとに自動停止します。人対AIでは、この200手の自動停止はありません。

「速い」「じっくり」で読む深さと計算量を切り替えられます。AIは駒の価値・利き・成り・王手などを使う簡易探索で、競技用の将棋ソフトほどの強さはありません。ブラウザ内の Worker で動き、APIキーや外部サービスは不要です。

## 対応ルール

- 全8種類の駒と成駒の動き、駒を飛び越えない移動、手番の切り替え。
- 捕獲、成駒を元に戻して持ち駒にする処理、駒打ち、任意・強制の成り。
- 二歩、行き所のない駒打ち、王手放置・自玉を王手にさらす手、打ち歩詰めの禁止。
- 王手表示、詰みの判定、投了、千日手、連続王手の千日手。
- 合意による引き分け。

ルール確認の基準：[日本将棋連盟の対局規則](https://www.shogi.or.jp/match/taikyoku_rules/)。千日手は「指し直し」として対局を終了し、「新しく始める」で再開します。入玉宣言法、持将棋の点数判定、500手による持将棋、持ち時間・秒読み、オンライン対戦は未実装です。

将棋の対局ロジックは以前の汎用ルールエンジンから独立しています。現在は盤面サイズ・初期配置・駒の動きとデザインを編集し、新しい種類の駒を追加できます。既存の駒は `src/pieces.ts` の `PIECE_DEFINITIONS` に設定データとしてまとめ、対局処理・画面・AIが参照します。配置ごとの変更は `pieceRules` に保存し、移動／駒取りは `normal`／`promoted`、見た目は `design`、追加駒の定義は `definition` に保持します。標準の定義は変更しません。追加効果と勝利・引き分けの判定は `ruleScript` のJavaScriptコードで拡張できます。

駒の `moves` は空きマスへの移動、`captures` は相手の駒を取る動きを設定する、それぞれ独立した `{ dx, dy, range }` の配列です。共通設定の編集では同じ内容を両方に保存します。個別設定を選んだ状態は `normal`／`promoted` の `separateCapture: true` で保持し、この指定がない旧データでは両配列の動きが異なる場合に個別設定と判定します。既存の将棋の駒には両方に同じ動きを設定しています。どちらかを `[]` にすると、移動だけ・駒取りだけの駒も表せます。王手・王の移動先の安全性・AIの利きの評価には `captures` を使い、空いている攻撃先や味方の駒を守るマスも利きとして扱います。

`dx` は盤面の右方向を正、`dy` は駒の前方を正とし、後手では `dy` の向きを反転します。`range: 1` は指定した移動先へ1回移動し、`range: null` はその方向へ盤端または駒にぶつかるまで繰り返します。正の整数ならその回数まで繰り返します。移動用・駒取り用のどちらの経路も、最初の駒にぶつかると止まります。桂馬は `{ dx: -1, dy: 2, range: 1 }` と `{ dx: 1, dy: 2, range: 1 }` で、途中のマスを調べず移動先を判定します。

例えば、設定データを次のようにすると「前へ1マス進み、斜め前の相手を取る」基本動作を表せます。駒の通常状態と `promotion` の両方に、移動用・駒取り用の配列を設定します。

```ts
moves: [{ dx: 0, dy: 1, range: 1 }],
captures: [
  { dx: -1, dy: 1, range: 1 },
  { dx: 1, dy: 1, range: 1 },
],
```

`promotion` がある駒は成ることができ、成り後の名前・動き・価値を定義します。`promotion.forcedRanks` は、成らずに残れない相手側の端からの段数です（歩・香は1、桂は2、飛・角・銀は0）。この段数は駒打ちの制限にも使います。王手・二歩・打ち歩詰めなどの将棋ルールは対局処理で判定します。保存済みの配置と棋譜は引き続き読み込めます。

## 編集のテスト・復元・補助操作

盤面編集、駒設定、コード編集の「この下書きをテスト」「このコードでテスト」から、編集中の設定を試せます。テスト中は本番の対局と編集の下書きを保持し、テストの指し手・AI設定・盤面反転は本番へ保存しません。手動操作、AIで1手進める、一手戻す、最初から試すに対応し、「編集に戻る」で元の画面・書き途中のコードへ戻れます。テスト中に再読み込みした場合は、タイトルの「編集を再開」から下書きを復元できます。

テストの実行ログには、盤面／駒の種類・マス番号・イベント名、駒の生成・破壊・移動・変身、個別データ・共有データ・持ち駒・乱数・勝敗の変更を表示します。コードが何も変更しなかったイベントも区別できます。画面には直近20手と開始時のログを表示し、「ログをJSON保存」では設定と全手の記録、現在の状態を保存します。通常の棋譜には詳細ログを含めず、コードと指し手から再現します。エラーが発生した手は反映せず、編集に戻って修正できます。

編集内容は通常の対局・名前付き配置とは別の `shogi-editor-draft.v1` キーへ自動保存します。盤面、駒設定の未反映の下書き、書き途中・構文エラーのあるコード、個別データの入力途中も復元対象です。タイトルやエディットのメニューに「編集を再開」が現れ、元の編集画面から再開できます。下書きの読み込み時にコードは実行しません。編集を明示的にやめた場合と「この配置で対局」を適用した場合は下書きを終了します。下書きの保存容量不足は画面に表示し、以前の保存済み配置や本番の対局を上書きしません。

盤面編集・駒設定・コード編集には「やり直す（Redo）」を追加しています。取り消した後に別の変更を加えるとRedoの枝を破棄します。入力欄以外ではCtrl+Zで取り消し、Ctrl+Y／Ctrl+Shift+ZでRedoできます。入力欄では通常の文字編集のショートカットを使い、IME変換中には編集画面のショートカットを実行しません。Undo／Redoの履歴は現在の編集セッション内で保持し、再読み込みからは下書きの状態を復元します。

### 基本ルール・王の役割・初期データ

盤面編集の「基本ルール」で、王手・王手放置、二歩、打ち歩詰め、持ち駒／駒打ちを個別に切り替えられます。成り範囲は標準（盤面に応じて最大3段）、端から1〜15段、成りなしを選べます。設定は `position.settings` に保持し、合法手、AI、スクリプトによる捕獲、パス、勝敗判定、保存・再開にも適用します。標準設定では従来の将棋の動作を維持します。持ち駒を無効にすると捕獲した駒を手へ加えず、既に設定した持ち駒も対局中には使用しません。成りなしでは強制成りと成り前の最終段制限も無効になります。

駒設定の「王として扱う」で、王の役割を任意の種類へ移せます。役割を有効にした種類の駒は、各側の盤面に合計1枚必要です。通常の王以外を使う場合はKの役割を無効にし、新しい王の種類を有効にします。王手を判定する場合は王となる駒の安全性を守り、王手なしでは王となる駒の捕獲によって終局できます。すべての種類の王の役割を無効にした場合は王の配置を要求せず、盤面コードなどで勝敗条件を設定できます。

種類ごとの「初期データ」はJSONオブジェクトで設定できます。例：`{"hp":3,"uses":2}`。盤面の「選択・データ」ツールで駒を選ぶと、その個体だけの初期値を設定できます。同名のフィールドは個別設定を優先し、対局開始時に種類の初期値と合成します。駒打ち・コードでの生成では種類の初期値から作成し、変身では新しい種類の初期値へ既存の個別データを重ねます。対局中の変更はこれまでどおり `ctx.setPieceData` で行います。コードからは `ctx.settings` と `ctx.royalTypes` で設定を参照できます。

盤面左側に先手・後手それぞれの「初期持ち駒」の駒置き場があります。右の「置く駒」で種類を選び、追加したい側の「＋ ○○を置く」を押すと1枚ずつ追加します。置き場の駒をクリックすると枚数（0〜225枚）を指定でき、Enterまたは「枚数を反映」で確定、0枚で取り除けます。Escまたは「閉じる」では枚数を変更せずに閉じます。成りを選んでいても持ち駒は成り前になり、王の役割がある種類は持ち駒にできません。追加・枚数変更はUndo／Redo、自動保存・復元、配置ファイルにも対応します。基本ルールまたは種類の初期データ・王の役割を含む配置はversion 6、棋譜はversion 8で保存します。以前の配置・棋譜も読み込めます。

### 配置の操作補助

「配置」は従来の駒の配置、「選択・データ」は盤面を変更せず個体を選択、「移動」は元と先の順にクリックして駒を移動します。「範囲コピー」は2つの角を押して長方形を選び、貼り付け先の左上をクリックします。空きマスも含めてコピーし、元の範囲を維持します。盤外へは貼り付けず、駒の独自データはコピー元と独立させます。左右反転・上下反転と、180度回転して先後・持ち駒・最初の手番を交換する操作も利用できます。それぞれUndo／Redoの1操作として扱います。

## JavaScriptのルールコード

盤面と駒には別々のコードを設定できます。盤面編集の「盤面のルールコードを編集」では、勝利・敗北条件や盤面全体の効果を記述します。「駒の設定画面を開く」→種類を選択→「この駒のルールコード」では、その種類だけの動作を記述します。両方のコードを同じ配置に保存でき、これまでの盤面コードもそのまま利用できます。

駒のコードは同じ種類の先手・後手、通常・成り後で共有します。`ctx.self.side`や`ctx.self.promoted`で条件を付けられます。HPや使用回数などは各駒の`data`に保存し、盤面・全駒で共有する情報には`ctx.state`を使います。

例えば、次のコードを対象の駒へ設定すると、その駒だけが「取られると消滅」します。

```js
export default {
  afterCaptured(ctx) {
    ctx.discardCapture();
  }
};
```

駒のコードのイベントは次の対象に発動します。`ctx.self`はコードを持つ駒の参照用コピーで、`square`・`type`・`side`・`promoted`・`data`・`alive`を参照できます。`ctx.actor`はイベントを起こした駒です。捕獲時には、取る側がactor、取られた側のコードではselfが取られた駒になります。

| イベント | 駒のコードの対象 |
| --- | --- |
| onStart | 開始時に盤面へ配置された各駒 |
| validateMove / beforeMove | これから動かす・打つ駒 |
| beforeCapture / afterCapture | 相手を取る駒 |
| afterCaptured | 相手に取られた駒 |
| afterMove | 動いた・打った駒。自動移動も含む |
| afterDestroy | 破壊された駒 |
| turnStart / turnEnd | その手番の持ち主の駒それぞれ |

各イベントでは盤面のコード、対象となる駒のコードの順に実行します。手番イベントでは盤面のマス番号順に対象を決め、途中で除去・別の種類へ変更された駒を再度動かしません。同じ場所へ新しく生成した駒も、元の駒のイベントを引き継ぎません。取られた・破壊された駒は`ctx.self.alive === false`となり、除去前の情報を参照できます。消えた駒には、その後のafterMoveを発動しません。afterCapturedのself.squareには捕獲先のマスが入るため、そのマスをdestroyすると現在そこにいる捕獲側の駒を破壊できます。

駒の効果と追加イベントをすべて解決した後に、盤面の`checkResult`を実行します。勝利・敗北条件は引き続きここで設定できます。checkResultは盤面専用のイベントです。駒のコードからも`ctx.win`・`ctx.draw`を使えますが、盤面のcheckResultで設定した結果を最終的に使います。捕獲側・捕獲された側・盤面でdiscardCaptureを重ねて呼んでも、捕獲した持ち駒を除外するのは1回です。

駒のコード編集も独立した下書きです。「設定を反映して戻る」で駒設定の下書きへ反映し、さらに駒設定から盤面編集へ反映します。駒設定の「変更せず戻る」では、その中で編集したコードも破棄できます。各段階の取り消し、駒のコピー、新しい種類の駒へのコピー、配置のコピー・別名保存・ファイル出力、待った・保存・再開・AIにも両方のコードを含めます。駒のコードを含む配置はversion 5、棋譜はversion 7で保存し、盤面だけのコードのversion 4／6も引き続き読み込めます。

盤面編集の「盤面のルールコードを編集」から、この配置全体に適用するJavaScriptを記述できます。`if`・ループ・関数・計算・配列・オブジェクトなどを利用できます。「サンプルを読み込む」には、周囲破壊、捕獲された歩の消滅、手番開始時の歩の自動前進、最終段での選択式変身を用意しています。通常の駒の移動先は従来の駒設定で決め、コードから追加効果や指し手の禁止、勝敗判定を設定します。

```js
export default {
  afterCapture(ctx) {
    for (const target of ctx.board.neighbors(ctx.event.to)) {
      if (target.piece && target.piece.side !== ctx.actor.side) {
        ctx.destroy(target.square);
      }
    }
    ctx.state.explosions = (ctx.state.explosions ?? 0) + 1;
  }
};
```

コードは下書きとして編集し、「実行確認」で構文、現在の配置の開始処理、先頭64件までの合法な行動とパスを検証します。確認は盤面を変更しません。「設定を反映して戻る」で盤面編集の履歴へ反映し、「変更せず戻る」または Esc で破棄します。Ctrl+Enter（MacではCommand+Enter）でも実行確認でき、Tabはコード欄へ空白2文字を挿入します。盤面編集での取り消し、配置のコピー、別名保存、ブラウザ保存、ファイル出力、棋譜保存にもコードを含めます。盤面のコードだけを含む配置はversion 4、棋譜はversion 6です。駒のコードを含む場合は配置version 5、棋譜version 7です。従来の保存形式も読み込めます。

### イベント

`export default` に次の名前の同期関数を定義します。必要なイベントだけを記述します。

| 名前 | 実行時点 |
| --- | --- |
| `onStart` | 初期配置から対局を開始するとき |
| `validateMove` | 指し手を適用する前。`false`で禁止 |
| `beforeMove` | 通常の指し手を適用する前。駒打ち・パスも対象 |
| `beforeCapture` | 通常・自動移動で相手を捕獲する直前 |
| `afterCapture` | 相手を捕獲して、持ち駒に加えた後 |
| `afterCaptured` | 取られた駒への通知。盤面でも捕獲情報を参照可能 |
| `afterMove` | 通常・自動移動・駒打ちの後。パスでは発生しない |
| `afterDestroy` | 破壊で盤面から除去された後 |
| `turnEnd` | 指した側の手番終了時 |
| `turnStart` | 次の側の手番開始時。初期配置でも1回発生 |
| `checkResult` | 一連の効果が終わり、通常の王手・勝敗を判定する前 |

基本の順序は、validateMove → beforeMove → 捕獲・移動 → afterCapture → afterCaptured → afterMove → turnEnd → 手番交代 → turnStart → checkResultです。効果による変更は即座に盤面へ適用し、追加のafterMove・afterCapture・afterCaptured・afterDestroyは発生順のキューで処理します。beforeCaptureは捕獲処理の中で同期的に呼びます。このイベントで元や先の駒を除去・交換すると、その手はエラーになります。捕獲後の消滅にはafterCapture／afterCapturedの`discardCapture()`を使ってください。

### スクリプトAPI

マス番号は左上の0から横方向に並びます。先後のIDは`"sente"`／`"gote"`、駒のIDは`"P"`、`"R"`、`"custom_1"`などです。`ctx.event`には`from`・`to`・`piece`・`captured`・`side`・`automatic`・`pass`がイベントに応じて入ります。`ctx.actor`は対象の駒の参照用コピー、`ctx.side`は盤面コードではイベントの側、駒コードではその駒の持ち主、`ctx.turn`は手番、`ctx.ply`は完了した手数です。

| API | 動作 |
| --- | --- |
| `ctx.board.snapshot()` | 盤面配列のコピー |
| `ctx.board.isAttacked(マス, 先後, 仮の盤面?)` | 指定側の駒の「駒取り」の利きが届くか。仮の盤面配列も指定可能 |
| `ctx.board.at(マス)` | 駒またはnullのコピー |
| `ctx.board.pieces(先後?)` | `{square, piece}`の配列 |
| `ctx.board.neighbors(マス, 範囲=1)` | 周囲の`{square, piece}`の配列。中心を除外 |
| `ctx.board.forward(マス, 先後, 歩数=1)` | 前方のマス番号。場外ならnull |
| `ctx.hands`／`ctx.pieceTypes` | 持ち駒の参照用コピー／使用可能な駒のID配列 |
| `ctx.move(元, 先)` | 空きマスへ自動移動 |
| `ctx.capture(元, 先)` | 指定先へ自動移動し、相手がいれば捕獲 |
| `ctx.capturePiece(捕獲する駒, 取られる駒)` | 捕獲側を移動させずに捕獲し、通常の捕獲イベントを通知 |
| `ctx.destroy(マス)` | 持ち駒にせず除去 |
| `ctx.discardCapture()` | afterCapture／afterCaptured内で、捕獲した駒を持ち駒から除外 |
| `ctx.spawn(マス, 種類, 先後, 成り=false)` | 空きマスに駒を生成 |
| `ctx.transform(マス, 種類, 成り=false)` | 種類を変更し、先後と独自データを維持 |
| `ctx.changeSide(マス, 先後)` | 駒の所属を変更。種類・成り・独自データを維持し、捕獲・破壊イベントは発生しない |
| `ctx.choose(見出し, 候補配列)` | 選択された文字列。候補は文字列または`{value,label}` |
| `ctx.choosePiece(マス, 種類配列, 見出し?)` | 選択した駒へ変身 |
| `ctx.state` | 対局全体の独自データ。フィールドを変更して保存 |
| `ctx.setPieceData(マス, オブジェクト)` | 駒ごとの独自データを設定。参照は駒の`data` |
| `ctx.random()` | 再現可能な0以上1未満の乱数 |
| `ctx.reject(理由?)` | この指し手を禁止 |
| `ctx.win(先後)`／`ctx.draw()` | 勝利・引き分けを確定 |
| `ctx.draw({unlessMate:true})` | 同じ手の詰みを優先する引き分け |
| `ctx.setRepetitionKey(文字列)` | 同一局面と見なすキーを指定（4,000文字まで） |
| `ctx.allowDrawClaim(理由)` | 現在の局面で引き分け申請を許可 |
| `ctx.checkDrawClaimAfterMove()` | 次の1手で申請可能になるか調べる操作を許可 |
| `ctx.log(文字列)` | 棋譜の効果履歴へ記録 |

自動移動は駒の通常の移動設定を経由せず、指定したマスへ動かします。イベントの`automatic`で通常の操作と区別でき、無条件に自動移動を繰り返す連鎖を避ける条件も書けます。王の役割を持つ駒が捕獲・破壊・変身などで消えると、残った側が勝ち、両方が消えると引き分けになります。王の役割を全種類で無効にした場合は、この判定を行いません。`win`・`draw`で明示した結果を優先し、それ以外は効果が完了した盤面で有効な基本ルールと将棋の勝敗を判定します。

選択は指し手を行う側が行い、成りの選択と併用できます。選択の結果を指し手に記録し、AIでは各選択肢を別の手として探索します。開始時のonStart・turnStartでは選択を要求できません。コードは合法手の判定やAIの探索でも繰り返し実行するため、モジュール内の変数は手ごとに初期化します。継続する情報は`ctx.state`か駒の`data`に置いてください。独自データ・乱数・自動効果も待ったと保存・復元の対象です。コードから手数を参照できるため、通常は手数や独自データの異なる局面を別の局面として扱います。`setRepetitionKey`を使う場合は、そのキーで同一性を指定します。盤面の基本ルールで同一局面の自動終局を無効にし、盤面コードで独自の回数条件を処理することもできます。

JavaScriptの実行には[QuickJS](https://github.com/justjake/quickjs-emscripten)を使用し、ブラウザ・通信・ファイル・外部importから独立させています。同期実行のみ対応し、Dateは使わず、乱数はctx.random()を使います。コード上限30,000文字、各実行のメモリ16MiB、スタック512KiB、割り込み回数256回または150ms、1手256操作・128イベント・4回の選択（各32候補）、選択分岐の探索128回までです。エラー・過剰な処理・保存できない独自データはその手全体を取り消します。

実装は`src/rulescript.ts`（API・イベント・サンプル）、`src/scriptvm.ts`（独立実行環境）、`src/scripteditor.ts`（編集画面）、`test/rulescript.test.ts`／`test/piecescript.test.ts`／`test/script-ui.test.ts`（盤面・駒のルールと画面の検証）です。配信用の実行エンジンはBunで単一ファイルにまとめ、開発サーバーと静的配信の両方で利用します。

`bun run dev`／`npm run dev`はwatchモードで起動し、サーバーの変更時に再起動します。既に古いコマンドで起動していたサーバーは、一度停止して起動し直してください。起動時の読み込みに失敗した場合は、エラーの詳細と再読み込みボタンを表示します。`test/startup.test.ts`は実際のHTTP配信からモジュールを取得し、ブラウザーで解決できるimportであること、Nodeのprocessを使わずタイトル画面・スクリプトを実行できること、読み込み失敗時の表示を検証します。

タイトルでは保存済み対局の名前・盤面サイズ・手数・手番の概要だけを読み、棋譜の検証と再現は「対局の続きから」を押した時に行います。長い棋譜は8手ずつ復元し、その間も画面を更新します。復元のキャンセルやメニュー移動では元の保存を変更しません。全手の検証、Undo、反復履歴、ルールの効果は従来どおり維持します。

コード実行エンジンは`src/scriptvm.ts`の軽量な窓口と、必要時に読み込む`src/scriptengine.ts`に分かれています。タイトル・通常の将棋・通常の将棋AIでは大きな実行エンジンを読み込みません。チェス、ルールコード付きの対局・保存配置・下書き、コード編集を初めて使う時に読み込み、以降は再利用します。初回読み込みに失敗した時は再試行できます。CLIからは従来どおり同期の対局APIを利用でき、ブラウザーでルール付き対局をコードから作る場合は先に`await prepareRuleEngine()`を呼びます。`ShogiGame.loadAsync()`では進捗・中断を指定して棋譜を復元できます。
